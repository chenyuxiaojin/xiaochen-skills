# cyxj-deeper · 做深，不做大

方法论来自 Felix Rieseberg《How to be more ambitious: A tutorial for humans with models》
（https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/ ，2026-10-13）：
模型的能力早已远超大多数人的用法，真正的瓶颈是人不敢要。这个 skill 的任务是替用户把要求**往深处**提——
不是加更多功能、更多页数，而是做成这个领域顶尖的人会交出的那个版本。

用户是非程序员——解释直白，术语第一次出现就一句话说清。

## 流程（三步，顺序执行）

### 第 1 步：四问（动手前必须答完）

先从对话上下文、项目文件、`~/项目/内容创作/log/index.md` 推断任务背景，推断得出来的不许再问。然后逐条回答：

1. **顶尖的人会多做什么**：这个领域顶尖的从业者/创作者，在这里会多做哪些用户没要求的事？
2. **最原始的材料**：他们会从哪种最原始的材料起步——后台数据、评论区、原片素材、一手来源、原始数据——
   而不是别人已经消化过的二手总结？
3. **具体方法和工具**：他们会用哪些具体方法和工具？要**真的去用**（跑数据、做对照、写脚本、抽帧），
   不是只换一套专家口吻。
4. **外部裁判**：除了模型和用户之外，什么能证明结果是对的？平台数据、可自动跑的检查脚本、对照样本、
   真实观众反馈。**不许模型给自己打分。**

涉及外部事实（平台规则、工具能力、行业做法）要联网查证，查不到就标「未验证」，不许拿记忆冒充事实。

### 第 2 步：重写任务，给用户确认

把原任务重写成深度版，格式：

```
## 结论（一句话：深度版要交付的结果，用动词定义）

## 四问
1. 顶尖的人会多做：……
2. 起步材料：……（在哪、能不能拿到）
3. 方法和工具：……
4. 外部裁判：……（怎么判对错，谁来判）

## 重写后的任务
（一段可以直接执行的需求）

## 需要你拍板的
（只列答案会改变做法的 1~3 个决定）
```

然后**停下等用户确认**。用户说「行/开干」才进入第 3 步；用户改了就按改的来。

### 第 3 步：执行

按确认后的深度版执行。过程中遇到「做不到」先别退回原版——换方法再试；真卡住了，说清卡在哪、
已经试过什么，再请用户决定。交付时附上第 4 问的外部裁判结果（数据、脚本输出、对照），而不是自评。

## 原则（来自原文）

- **定结果，不派单任务。** 问一句「目标背后的目标是什么」：不是「修这个崩溃」，是「保证 app 不崩」；
  不是「改这篇稿」，是「这条视频在某平台达到某个数据」。前提是让模型自己能拿到反馈、能复现、能验证。
- **用专家的方法，而不是专家的用词。** 想用 markdown 表格糊弄的地方，坚持上数据库、统计、对照实验。
- **敢定不合理的目标，并当作合理去推。** 网页 10 秒加载，就直接要 200 毫秒；模型说做不到，告诉它能做到，让它继续。
- **用外部裁判。** 结果由数据、脚本、样本来判，不由模型或用户的感觉来判。
- **用动词定义作品。** 季度汇报不是「一份 PPT」，是「30 分钟内让忙碌的人信服一个因果故事」；
  一条视频不是「一个 3 分钟成片」，是「前 5 秒让刷到的人觉得这事和他有关」。
- **组专家队伍，但做他们会做的事，不角色扮演。** 编剧去拆结构、剪辑去看节奏、音频设计去测响度、
  红队观众去找划走点——每个角色交付他那一行真正会交付的东西，而不是模仿他的口气说话。

## 原文深度 prompt（原样保留）

> I want a deeper version of this task, not a bigger one. Before rewriting it: (1) say what a top professional in this field would do here that I'm not asking for; (2) name the rawest material they would start from instead of what has already been digested for me; (3) name the specific methods and tools they would use; (4) say what, other than you or me, would show the result is right. Then rewrite my prompt to ask for exactly that.

## 输出要求

- 中文，简短，结论先行。
- 四问每条一两句，说具体的东西（文件、数据、工具名），不说空话。

## 边界

- 只在触发词出现时启用；普通任务照常直接做。
- 第 2 步没确认前不开工。
- 「更深」不等于「更大」：不加用户没要的功能、不加篇幅，加的是标准、材料和验证。
