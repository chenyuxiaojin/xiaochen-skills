# cyxj-release-kit:视频发布物料一条龙

成片定稿 → 标题(6 平台)→ 简介(6 平台)→ 封面(4:3 首选,另含 16:9 / 3:4)→ 上传 JPG。
本 skill 把 2026-07-05 loop 视频那次全流程实战固化下来,核心教训只有一条:
**中文文字永远不要交给生图模型渲染**——模型不认精确比例、脚本会中心裁切,文字进画面必掉字;
文字由浏览器渲染,底图才交给生图/实拍。

## 前置

1. 读 `内容创作/log/index.md` HEAD,拿到:成片位置、**最终导出字幕**(SRT)位置、视频主题。
2. 确认**视频标题已定稿**。没定稿就先出候选 + 跑受众模拟(规则见模块一),用户拍板后再走后面模块。
   封面字案可以和标题不同(先例:封面只放问句「模型是如何看视频的？」,标题再接数字判决),封面不必等标题。
3. 所有事实(数字、时间戳、功能点)只从最终字幕/成片里来,**数据不编**(同 cyxj-jingxuan 的红线)。

## 模块一:标题(6 平台)

先读 `${CLAUDE_PLUGIN_ROOT}/skills/cyxj-release-kit/references/platform-specs.md`(各平台字数上限 + 自家高播放样本,必读)。

**标题只做一件事:对观众正在用 / 正在选的东西,给一个钩子。** 不再用「新闻导语式第三人称陈述句」当主公式
(证据:6 平台调研 534 条,每号≤3 条去重后,新闻导语式第三人称在任何平台都不是主流,2026-10-28)。
三类钩子,按平台和本期体裁选一类:
- **有分寸的情绪 / 判决**:「不如 / 贵 4 倍 / 翻车 / 别用」,程度词不超过片里的数字
  (证据:B站去重 136 号,含情绪/判决 44%;抖音去重 43 号约 18%,2026-10-28)
- **好奇缺口 / 反向劝退**:问句、「我现在不推荐你装了」类
  (证据:小红书 26 号,情绪 29%、第一人称 25%,反向劝退/态度类赞高于纯安装教程,2026-10-28;B站疑问 22%)
- **利益承诺**:「N 分钟学会 / 小白速通 / 附文档」——**只用在教程那期**,观察 / 实测 / 评测期不准用
  (证据:抖音腰部号多「数字+工具名+利益承诺」,2026-10-28;只用于教程期为用户拍板 2026-10-28)
工具 / 功能名靠前(证据:调研结论建议,未单独计数,待验证,2026-10-28)。
用户拍板的旧标准样本(2026-09-04):「Agent Teams 实测:3 个 AI 互相证伪排 bug,Token 贵 4 倍」——仍可作「判决」类参考,不再是唯一公式。

流程:
1. **先摘利害句**:从最终字幕 / 成片里摘 3-5 条——具体数字(倍数 / 刀 / 分钟 / 百分比)、判决(不如 / 贵 / 降智 / 删掉 / 别用)、
   观众身上正在发生的痛。摘不出来就如实回报用户"这期没有可卖的判决",等用户定方向。
2. **拼标题**:先按平台选钩子类型(见上),工具 / 功能名靠前,再接事件 / 数字。教程期才可用利益承诺类(待验证:具体哪类在自家号最好,看「每期发布记录」)。
3. **每平台 3 条候选**,各卖一条不同的利害句;每条附「前 15 字截断预览」;标一条推荐并说一句为什么。
4. **拍板前先跑受众模拟**(2026-10-15 起固定动作):把候选 + 封面描述喂给 `受众角色扮演` skill 的粉丝反应模式,
   至少 5 张卡(路人 / 泛科技 / 重度用户 / 挑刺同行 / 核心粉)隔离扮演,出「会不会点 + 看完会不会觉得被骗」两张表,
   报告落在项目目录 `标题受众模拟-<日期>/汇总.md`。用户看完报告再定句;拿不准的上 YouTube 后台「标题测试」让数据选。
   先例:10-15 六种写法里,封面原句单独当标题五人全不点;「实测」版五人全判被骗;「你发的视频」版点击最高但四人看完说名不副实。
5. **自检**(逐条过):在该平台长度区间内?工具名靠前?钩子类型和体裁匹配(非教程期没用利益承诺)?标题里每个事实片里都有?

长度(交付前数一遍,按平台分开):
- YouTube:中文 18–30 字,英文 30–60 字符(证据:YouTube 去重 105 号,英文中位约 38–46、中文教程 18–36,2026-10-28)
- B站:钩子型 12–26 字;教程型 30–45 字,可带【】(证据:B站去重 136 号,【】40%,新样本优秀组中位约 31 字,2026-10-28)
- 抖音首行 ≤20 字
- 视频号 ≤25 字(证据不足,待补样:调研仅 6 个号)
- 小红书约 20 字(证据:小红书 26 号,TOP 中位约 22 字,2026-10-28)
- TikTok:一句口语(证据:TikTok 24 号,爆款常一句口语,2026-10-28)

写法要求(只说要怎么写):
- 工具 / 功能名靠前,只写一次,英文名直接用(待验证)
- 一条标题一个钩子;有数字就用片里的具体数字(证据:B站数字 43%、YouTube 数字 50%,2026-10-28)
- 体裁词 = 片子的真实体裁(实测 / 对比 / 拆解 / 教程),标题里的每个事实都能在片中找到;**「实测」只在片里真有实测时写**,
  测了但没剪进成片也不能写——模拟里五张卡全判「标题卖实验给课件」,连带片里其他数字都被怀疑
  (证据:受众模拟 2026-10-15)。**事实红线:片里没有的事不写进标题**
- 标题必须带封面上没有的新信息:封面字案是问句或短句时,标题要接一句数字判决,封面原句单独当标题没人点(证据:受众模拟 2026-10-15)
- 第二人称钩子(「你发的视频」「你正在用的」)**点击是否最高:待验证**(只有 2026-10-15 一次受众模拟,无真实数据);
  用时要用片里原话的数字,不加「根本没看」这类比内容激进的程度词;观众冲着「那我该怎么办」进来,片尾或简介里要有一句落点
- 各平台卖同一个核心事实,钩子类型和长度按平台调(待验证)

## 模块二:简介(6 平台)

规格逐平台见 platform-specs.md。要点:
- YouTube 简介带章节时间戳,第一条必须 `00:00`,**每个时间戳都要回字幕核对**,禁止估。
- YouTube 简介补「链接区」(本期提到的工具 / 文档 / 仓库链接)(证据:YouTube 去重 105 号,链接区普遍,2026-10-28)。
- 抖音简介和标签段照 platform-specs.md 抖音节原样,不动。
- 标题+简介成对交付,一次给全 6 个平台,别挤牙膏。

## 模块三:封面(HTML 封面工作台)

### 3.1 底图(一期一张,无字)

底图 = 16:9 无文字场景图,来源二选一:

- **生图**:调 cyxj-image-studio 的 `generate.py`,**必须显式指定风格**:

  ```bash
  S=~/.claude/plugins/.../cyxj-video-cover/scripts/generate.py
  # 真人底图(人在左、右半边留白):
  python3 $S --title "本期标识" --style plate --ratios 16:9 --n 3 \
            --face ~/Pictures/封面形象/<用户指定的原图> --label "<项目>-底图"
  # 无人底图(不喂脸,走文生图端点):
  python3 $S --title "本期标识" --style plate-noface --ratios 16:9 --n 3 --label "<项目>-底图"
  ```

  **`--style` 不给就是 default,那会把中文标题渲进画面,出来是带字整图,不能当底图。**
  plate / plate-noface 的 prompt 完全不含 title,并且写死了「无任何文字/字母/数字/logo/水印」
  + 「右半边整片空墙留给排版」。`--title` 在这两个风格里只是批次标识,不进画面。

  人脸参考用 `~/Pictures/封面形象/` 里**用户指定的原图**(**每次都喂原图,严禁拿生成图回喂**,
  会越来越不像)。目录里有十几张,**别默认取第一张——先问用户用哪张**。

- **实拍/抽帧**:用户给照片,或从成片开头口播段 ffmpeg 抽帧(注意挑眼睛睁开的帧,先抽 5-6 帧给用户选)。

底图只出 16:9 一个比例——其余比例由工作台的 blur-fill 自己适配,不要分比例生图。

### 3.0 封面字与比例(2026-10-28 调研后补充)

- **4:3 保留**:B站和抖音的横封面要用(证据:用户拍板 2026-10-28)。
- 抖音 3:4 竖封面:字在上、人在中下(证据:抖音去重 43 号,优秀样本多为字上人下,2026-10-28)。
- YouTube / B站 16:9:封面字短,≤8 汉字,且是标题的**补充**不是复述(证据:YouTube 105 号、B站 136 号,封面字多为标题补充、文字海报型,2026-10-28)。
- **配色先不改规则**:每期出两版配色——现行**白+橙**与**白+黄**——给用户自己挑(证据:调研见黄+白常见但未验证对本号更好,待验证;两版并出为用户拍板 2026-10-28)。
  `导出.sh` 已一次出两版:`封面_<比例>.png/jpg`(白+橙)与 `封面_<比例>_黄.png/jpg`(白+黄),各带一张三比例拼图。
  编辑器里预览黄版:地址后加 `?accent=yellow`。

**通道的坑(2026-08-25 实测,踩过一遍才跑通)**:

| 现象 | 真因 | 处理 |
|---|---|---|
| 503 `No available channel for model gpt-image-2-vip` | 这把 key 的分组里**没有 vip 档** | 用 `gpt-image-2`(已是脚本默认);先 `GET /v1/models` 看分组里到底有啥 |
| 自写脚本 403 `error code: 1010` | **Cloudflare 拦 `Python-urllib` 的 UA** | 请求和下图都要带浏览器 UA;`generate.py` 已内置 |
| 400 `only supports image generation ... text conversation` | 上游偶发把图片请求错路由到对话模型,**成功率约五成** | 原样重试即可;`generate.py` 已内置 4 次重试 |
| 524 | Cloudflare 网关超时(~100s),并发越高越容易撞 | 并发别开太大 + 重试。实测并发 6 → 3 成功(36/63/89s)/3 个 524 |

已作废的旧说法:「gpt-image-2 会无视 size、强制 1254² 缩水,比例要稳得走 Gemini」——
2026-08-25 实测传 `size: 2560x1440` 就出 2560×1440,不必绕道。

### 3.2 封面编辑器(2026-10-15 起首选;用户自己拖位置,不用来回对话)

1. 把 `${CLAUDE_PLUGIN_ROOT}/skills/cyxj-release-kit/templates/cover-editor.html`、`cover-export.sh` 复制到本期
   物料目录 `~/Pictures/封面出图/<日期>-<项目>-最终/源文件/`(编辑器可改名「封面编辑器.html」,导出脚本里的文件名跟着改),
   底图按 `plate_p1.png、plate_p2.png …` 命名放同目录(一次出 3–6 张给用户挑),字体 ttf 也放进去。
2. 改编辑器顶部:`PROJECT`(项目名)、`PLATES`(底图列表)、`DEFAULT_TEXT`(白字 l1 / 可选 l2 / 橙字 l3)。
   `FACTORY` 是三比例出厂位置,真人底图通常不用动。
3. `open -a "Google Chrome" 封面编辑器.html` 交给用户:顶栏切比例、换底图、改字;人物 / 文字 / 箭头按住拖,
   顶栏「大小」− ＋ 或滚轮缩放,方向键微调;三比例各存各的位置,文字和底图共用。布局自动存 localStorage。
4. 导出:用户点「保存布局」→ json 落 ~/Downloads → 运行 `导出.sh`(默认取 ~/Downloads 最新 `封面布局-*.json`,
   复制为 `源文件/布局.json`)→ 无头 Chrome 出 `封面_16x9/4x3/3x4.png + jpg` + 三比例拼图并打开。
   用户没点「保存布局」就从 Chrome leveldb 里抠(key `coverEditor_<项目名>`):
   ```bash
   cd ~/Library/Application\ Support/Google/Chrome/Default/Local\ Storage/leveldb
   python3 - <<'PY'
   import glob,os,re,json
   best=None
   for f in sorted(glob.glob('*.log')+glob.glob('*.ldb'),key=os.path.getmtime):
       b=open(f,'rb').read()
       for m in re.finditer(rb'\{"text":\{"l1".*?"ratios":\{.*?\}\}\}',b,re.S):
           try: json.loads(m.group(0).decode()); best=m.group(0).decode()
           except Exception: pass
   print(best)
   PY
   ```
   取最后一条,存成 `源文件/布局.json`,`./导出.sh 源文件/布局.json`。
5. 底图不满意的点(2026-10-15 先例):用户要「人物大一点、字大一点」在编辑器里自己解决;要「背景渐变更干净」
   试过两条路都被否——整图叠暗角 / 提亮盖层会把人也压暗或冲灰;Vision 抠人 + 纯 CSS 渐变背景被评「太丑」。
   最后保留照片底图 + 轻暗角(编辑器 `.grad`)。`templates/fgmask.swift` 是 macOS Vision 抠图脚本,留着备用。

### 3.2b 旧画廊工作台(只在需要一次看 3 样式 × N 底图全组合时用)

1. 把 `${CLAUDE_PLUGIN_ROOT}/skills/cyxj-release-kit/templates/cover-studio.html` 复制到本期
   物料目录(`~/Pictures/封面出图/<日期>-<项目>-最终/源文件/`),底图重命名为 `plate_16x9.png` 放同目录。
2. 改模板顶部三个常量 `L1/L2/L3`(标题三段)。字数和默认(5/4/4 字)差很多时,按
   「字数 × 字号 ≈ 可用宽度」调 `RATIOS` 里各比例的 `s1/s3`,渲一次画廊自检确认没有换行/贴边。
3. `open -a "Google Chrome" 工作台.html` 给用户挑。4:3 排在最前,画廊 = 3 比例 × 3 样式(A 右栏三行+箭头 /
   B 通栏大字 / C 微倾斜+橙底线),点选存 localStorage,可多选。所有样式右上角都不放图标。
4. 读用户选择:**扩展碰不了 file:// 页面**,从磁盘读:
   ```bash
   cd ~/Library/Application\ Support/Google/Chrome/Default/Local\ Storage/leveldb
   strings -a $(ls -t *.log | head -1) | grep -a 'coverPicks\|16x9-\|4x3-\|3x4-' | tail -3
   ```
   取**最后一条** JSON 数组为准。读不到就直接问用户选了哪几个编号。
5. 按选中变体逐张导出(无头 Chrome,像素级精确):
   ```bash
   C="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
   "$C" --headless --disable-gpu --hide-scrollbars \
        --window-size=<W>,<H> --virtual-time-budget=4000 \
        --screenshot=<输出>.png "file://<工作台绝对路径>?v=<变体ID>"
   ```
   尺寸:16x9=2560,1440;4x3=2048,1536;3x4=1536,2048。导出后 `sips -g pixelWidth -g pixelHeight` 验尺寸。

### 3.3 工作台原理(改样式/排错时读)

- **blur-fill 模糊延展**:清晰底图按宽度贴底,画布上方缺口用同图 `blur(60px)` 放大版补,
  清晰层顶部加 `mask-image: linear-gradient` 渐隐,接缝不可见。模糊层 `background-position`
  取景**纯墙区**(right center),否则人物鬼影会浮在模糊区。
- 人物大小由清晰层 `plateW` 控制,文字大小在 `RATIOS` 每比例配置里。
  · **真人底图**:竖版必须把人顶上来才够看 —— 3x4 实测 `plateW: 1536`(=画布宽)人物偏小,
    **2200 才合适**(超出画布的右半边被 overflow 裁掉,人在左侧不受影响)。
  · **无人底图**:纯背景,`plateW` 设成画布宽即可满幅铺开,16:9 还能 `fade:false` 免渐隐。
- 字号三档 `s1/s2/s3` 对应 L1/L2/L3,**`s2` 不写会回退成 `s1`**。L1/L2 字数差很多时必须分开给:
  例 L1「如何管理上下文?」(8 字) 与 L2「SUBAGENTS」(9 个拉丁字母 ≈ 4.5 汉字宽) 共用一个字号,
  L1 必超宽。拉丁字母按 ≈0.5 汉字宽估,汉字按「字数 × 字号 ≈ 可用宽度」估。
- 字体 = 得意黑 Smiley Sans,已装 `~/Library/Fonts/SmileySans-Oblique.ttf`;模板 @font-face 走
  `local()` + 同目录 ttf 兜底。新机器没装:GitHub `atelier-anchor/smiley-sans` releases 下载
  (v2.0.1 实测可用),cp 进 `~/Library/Fonts/`。
