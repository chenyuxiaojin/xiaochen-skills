# 字幕转文案（cyxj-subtitle-wenan）

把外文视频字幕变成可念的中文**文案**（逐字稿）。最终口播是照着文案念出来的，会带上念稿习惯；本 skill 负责的是文案本身。

**第一原则：保原意。**  
听懂原片在说什么 → 用说得出口的中文写出来。表达习惯只作用于**怎么说**，不能改掉原片意思。

核心路径：**听懂意思 → 按会怎么说写成文案**（禁止：英文 → 书面中文 → 硬拆字幕行）。

> 公开 skill 对照（2026-09）：外面没有完全对上的路径。吸收了「说得出口、别切成字幕、钩子与信息提炼」等规矩；不照搬 WPS 禁预览、默认分镜生图、「每句≤20 字」硬上限。

## 何时用 / 何时不用

**用：**
- 有 YouTube 链接、视频 ID、或已有 `.srt` / `.vtt`
- 要去订阅催促、片尾导流、自我推销
- 要改成说得出口的中文文案 / 逐字稿

**不用：**
- 只要查逻辑断点 → `dbs-script-flow` / `cyxj-content`
- 只要优化开头 → `dbs-hook` / `cyxj-hook`
- 达芬奇成片 SRT 修正 → `cyxj-subfix`
- 逐字稿整理成**文章** → `cyxj-transcript`（方向相反：去口语化成文）
- 用户明确要求「按我的观点重写 / 改成我的判断」→ 那是二次创作，先确认再写，并标明与原片的差异；默认不做

---

## 保原意（最高优先级）

1. 先用一两句话写下**原片核心论点**（作者的判断）。
2. 改写后的文案必须仍能对上这句论点；数据、因果、结论方向不得偷换。
3. 可以删广告、压缩啰嗦、调语序、改成口语；**不可以**加原片没有的主线、发明原片没有的经历或机制、把相反观点或空安慰写进原片没有的位置。
4. 正文默认忠实原意；未经用户点名，不做评论向重写。

自检：把文案给没看过原片的人听，其复述的中心思想是否还是原作者的？差很大 = 失败。

---

## 表达审美（只作用于「怎么说」）

写前读 `灵感库/已发布/` 里 1～2 篇**句式节奏**接近的成片，学的是：

- 一口气说完一件事；修饰语挂名词上
- 忌字幕栈（半成品短行排队）
- 数据嵌进句子里念，少「第一点第二点」板书腔
- 少主持腔总起（「今天我们来讲清楚」）
- 长短句交错，不以「每句≤20 字」为硬上限
- 可选保留已发布里真实出现的语气词习惯（对吧 / 说实话 / 这一个），**不臆造口头禅，不加戏改论点**

### 写稿两原则（2026-10-01 · 只作用于「怎么说」，原意不动）

**原则一：当面说测试。** 每句都要是人和人当面聊天时真会说出口的样子。

- 写完每一句，想象当面跟朋友说这句话；朋友听到的是什么样，稿里就写成什么样。
- 用词取平常说话的完整说法，口语感来自句子完整，用词保持规整：「Anthropic 三天前发布了 Sonnet 5.5，在它发布页的最下边，有一个很小的脚注」。
- 引用前先垫一句人话：「我去找遍了官方文档，里面其实已经写着这样一句话……」
- 英文先翻成日常说法再上稿，比如 overthinking 说第三方用「容易想得过多」。

**原则二：文案往动画展示靠。**

- 写每一句时，让句子本身带一个能画出来的物件、数字或动作，做动画的人听一遍就知道画什么。
- 这一条只管句子怎么写。稿子里只有口播：不写分镜、不写画面说明、不写 🎬 框（2026-10-16 定）。画面到做动画阶段再单独出。

去 AI 味：
1. 先过原则一的当面说测试，再对照已发布的**说法密度与口语节奏**
2. 用户当面改的句子立刻固化

讨厌的表达（不是讨厌原片观点）：
- 翻译腔、字幕栈、金句排比收束
- 通用短视频 Hook→Problem→Solution→CTA 模板腔
- 工整平均的 AI slop 句式

## 输入 / 输出

**输入：** 视频链接/ID、字幕文件、或纯文本；可选对照成稿、时长偏好。

**输出：** `灵感库/待发布/<标题>（逐字稿）.md`  
Frontmatter：来源、作者、处理说明、status、created、风格对照（句式样本）、**原片核心论点（一句话）**。  
正文以「逐字稿原文：」起头。  
交付：路径 + 开场预览 + 删了哪些广告。

库路径未设置 `CYXJ_VAULT_BASE` 时按 `~/obsidian/灵感库` 兜底，并向用户确认。

---

## 文案铁律

1. **保原意** > 表达习惯 > 其它润色。
2. 产物叫文案；口播是照着念。
3. 去广告导流，保留原片数据与判断。
4. 说得出口，不把长文切成字幕。
5. 口语化重组，不是直译，也不是换题重写。
6. 一条转写稿对准原片一个主论点（原片若有多个，按原片主线）。

## 工作流

### 1. 拉字幕并洗净
`yt-dlp` 优先人工字幕；去叠句/HTML/重复。

### 2. 去广告与导流
删订阅催促、无关自我介绍、片尾导流。

### 3. 锁定原意（不可跳过）
写出原片核心论点一句话；列出必须保留的关键数据/结论。

### 4. 按表达审美写文案
听懂 → 按会怎么说写；单位规则见上。  
结构跟原片论证走。

### 5. 落盘与交付
写入待发布；预览开场；若用户要「按我的观点重写」，另开一版并标明差异，默认版保持忠实。

自检：
- [ ] 原片核心论点是否原样成立？
- [ ] 有没有加戏导致意思漂移？
- [ ] 有没有字幕栈 / 翻译腔 / 模板腔？
- [ ] 大声读是否顺口？

---

## 质量标准

好稿：意思是原作者的，说法是说得出口的中文。  
差稿：意思漂移；或直译字幕栈。

## 明确不吸收的做法

- 「每句≤20 字」、WPS 禁预览、默认分镜生图
- 无样本的通用 Hook 模板腔
